# 架构

云计算指北 是一款**零后端**的 Manifest V3（MV3）浏览器扩展。获取云厂商状态、将其
与你的规则匹配、以及存储通知，全部在扩展内部本地完成。没有服务器、没有账号、也
没有遥测。

## 总体流程

```
chrome.alarms（周期性，默认 5 分钟）
        │
        ▼
后台 service worker
        │
        ├─ 1. 并行获取已启用云厂商的数据源
        ├─ 2. 将每个数据源解析为统一的事件结构
        ├─ 3. 归一化、去重并限制数量
        ├─ 4. 更新工具栏角标
        ├─ 5. 将状态写入 chrome.storage.local
        ├─ 6. 将新事件与本地订阅规则匹配
        └─ 7. 触发 chrome.notifications 并追加到本地历史
        │
        ▼
Vue 3 + Pinia 界面（弹窗 + 页面）
```

每个周期：

1. `chrome.alarms` 周期性触发。
2. 后台 service worker **并行**获取已启用云厂商的数据源。
3. 每个云厂商都有一个**解析器**，将其数据源转换为统一的事件结构。
4. 事件被**归一化**，然后**去重**（最严重的优先；同级时取最新的）并**限制数量**。
5. 更新工具栏**角标**，并将状态写入 `chrome.storage.local`。
6. 新事件与本地存储的订阅规则进行**匹配**。
7. 匹配项触发 `chrome.notifications`，并追加到本地通知历史。

## 解析器

每个云厂商的数据源都由专门的解析器转换为归一化事件：

| 云厂商 | 数据源类型 | 解析器 |
| --- | --- | --- |
| AWS、Azure | RSS | `fast-xml-parser` |
| Google Cloud | JSON | `incidents.json` 解析器 |
| 基于 Statuspage | JSON | Atlassian Statuspage 适配器 |
| 阿里云 | JSON | 定制适配器（未公开的 API） |
| 腾讯云 | JSON | 定制适配器（未公开的 API） |

阿里云和腾讯云通过未公开的 JSON API 暴露状态（其站点是没有通用数据源的 SPA），
因此为它们编写了定制适配器。

## 声明式云厂商注册表

云厂商注册表是**声明式**的。每个条目描述：

- 云厂商代码和显示名称
- 数据源 URL
- 解析器类型
- 官方状态页面 URL
- 来源 Origin（用于主机权限）
- 实验性标记

因此，添加一个云厂商是一项范围明确的小任务：

1. 一个注册表条目。
2. 一个解析器（或复用已有的）。
3. 一个 manifest 来源。
4. i18n 名称。
5. 一个测试。

## 存储布局

| 存储 | 内容 |
| --- | --- |
| `chrome.storage.sync` | 设置和订阅规则 |
| `chrome.storage.local` | 最新状态、通知历史、已见事件 ID 集合（用于去重）、可选的 LLM 配置 |

设置和规则存放在 **sync** 存储中，以便跟随浏览器配置文件。所有运行时数据——状态、
历史、去重状态以及 LLM 密钥——都存放在 **local** 存储中。LLM 密钥绝不同步。

## 故障隔离

故障是**按云厂商隔离**的。如果某个云厂商出错，它在该周期只是不贡献任何事件，并被
汇总到一个错误列表中。它绝不会让整次运行崩溃——其他云厂商仍会更新。

## 界面

界面采用 **Vue 3 + Pinia**。弹窗和页面从后台 worker 读取状态（在开发环境下则直接
获取）。

## MV3 约束

MV3 的 service worker 带来了两项值得注意的约束，云计算指北 对其做了规避：

- service worker 中**没有 `DOMParser`**，因此 RSS 使用 `fast-xml-parser` 解析，
  而非 DOM。
- **没有 Node 的 `crypto`**，因此用一个小的**同步哈希**来生成稳定的事件 ID
  以供去重。

## 它*不具备*什么

没有后端 API、没有数据库、没有认证/OAuth、没有遥测。唯一的对外请求是发往云厂商
状态数据源（由主机权限覆盖）以及可选的用户自有 LLM 端点。
